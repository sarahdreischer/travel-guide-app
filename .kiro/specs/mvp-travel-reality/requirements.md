# Requirements Document

## Introduction

MVPTravel Reality is a web application that surfaces real-world, practical travel advice for a curated list of destinations. Travellers fill out a form describing their trip context (dates, travel mode, budget, style, activity preferences), and AI models generate structured, categorised answers covering everything from rental cars and safety to laundry and local food. These AI-generated answers are persisted to avoid redundant queries. Users can vote on the accuracy of answers over time, improving the quality of content. The MVP covers 10 initial destinations and is built as a mobile-friendly Next.js web app backed by PostgreSQL.

---

## Glossary

- **System**: The MVPTravel Reality web application (Next.js frontend + backend).
- **User**: An authenticated person who has completed the new-user setup flow.
- **Guest**: An unauthenticated visitor.
- **Destination**: One of the 10 hard-coded travel locations supported at launch (e.g. Costa Rica, Mallorca).
- **Trip**: A user-created record combining a Destination with travel context (dates, mode, budget, style, activity preferences).
- **Category**: A named topic area (e.g. Transportation, Safety, Food & Tipping Culture) for which structured advice is generated.
- **Concise Card**: A summarised, single-topic card shown on the Home page.
- **Expanded Card**: A detailed view for a single Category, showing all sub-questions and AI-generated answers.
- **AI Advice**: Structured text generated by an LLM in response to a Category's questions, contextualised by a Trip's travel context.
- **Cache Key**: The tuple (destination, month, traveller_type, budget_range) used to de-duplicate AI Advice storage.
- **Vote**: A user action of 👍 Accurate, 👎 Outdated, or ➕ Add experience applied to a piece of AI Advice.
- **LLM_Adapter**: The backend service component that abstracts communication with one or more AI model providers.
- **Advice_Store**: The PostgreSQL-backed persistence layer for AI Advice records.
- **Auth_Service**: The component responsible for user authentication (email/password).
- **Profile_Service**: The component responsible for user profile management.

## Requirements

### Requirement 1: User Authentication

**User Story:** As a Guest, I want to log in with my email and password, so that I can access my personal trips and saved travel advice.

#### Acceptance Criteria

1. THE Auth_Service SHALL provide a login page with an email input field, a password input field, and a Login button.
2. WHEN a Guest submits credentials where the email matches a registered account and the password matches that account's stored password, THE Auth_Service SHALL authenticate the User and redirect them to the Home page.
3. IF a Guest submits credentials where either the email does not match a registered account or the password does not match, THEN THE Auth_Service SHALL display an inline error message that does not reveal whether the email or the password was incorrect, and the error message SHALL remain visible until the User modifies at least one input field or resubmits the form.
4. WHILE a login request is in flight, THE Auth_Service SHALL disable the Login button to prevent duplicate submissions.
5. IF a Guest has submitted incorrect credentials 5 or more consecutive times for the same email address, THEN THE Auth_Service SHALL lock that account from further login attempts for 15 minutes and SHALL display an inline message informing the User that the account is temporarily locked.
6. IF a Guest attempts to access an authenticated-only page without an active, non-expired session token, THEN THE Auth_Service SHALL redirect them to the login page.
7. WHEN an authenticated User's session token expires or is invalidated, THE Auth_Service SHALL redirect the User to the login page.

### Requirement 2: New User Setup

**User Story:** As a newly registered User, I want to complete a one-time profile setup, so that my account is personalised and I have acknowledged the platform's liability disclaimer.

#### Acceptance Criteria

1. WHEN a User's account is created for the first time, THE System SHALL present the new-user setup page before granting access to any other page, and SHALL NOT allow navigation away from the setup page until the form is successfully submitted.
2. THE System SHALL collect the following fields on the new-user setup page: first name (required), last name (required), email address (required), and profile image (optional upload).
3. WHEN a User submits the setup form and any of first name, last name, or email address is empty, THE Profile_Service SHALL display a field-level validation error on each empty required field and SHALL NOT save the record.
4. IF a User submits an email address that does not conform to the format local-part@domain.tld, THEN THE Profile_Service SHALL display a field-level validation error on the email field.
5. WHEN a User taps the form submission button and no validation errors are present, THE System SHALL display a liability disclaimer modal before submitting the form; the modal SHALL contain the disclaimer text, an explicit "I acknowledge" confirmation button, and a "Cancel" button.
6. IF a User taps the "Cancel" button or dismisses the liability disclaimer modal without tapping the "I acknowledge" button, THEN THE System SHALL close the modal, return focus to the setup page form, and SHALL NOT submit the form.
7. WHERE a User uploads a profile image, THE Profile_Service SHALL accept images in JPEG, PNG, or WebP format with a maximum file size of 5 MB; IF the uploaded file does not meet these constraints, THEN THE Profile_Service SHALL display a field-level validation error on the profile image field and SHALL NOT save the file.
8. WHEN a User successfully submits the setup form and acknowledges the liability disclaimer, THE System SHALL save the profile record and redirect the User to the Home page.

### Requirement 3: Add Travel Destination (Trip Creation)

**User Story:** As a User, I want to create a trip by selecting a destination and providing my travel context, so that the System can generate personalised travel advice for my trip.

#### Acceptance Criteria

1. THE System SHALL present an "Add travel destination" form containing the following fields: destination (select from 10 supported destinations), travel date range (start date and end date), travel mode (Solo / Friends / Couple / Family), budget range (a numeric value in USD, minimum 1, maximum 1,000,000), travel style (Adventure / Relaxed / Cultural / Luxury / Budget / Family), and activity preferences (multi-select: Hiking, Swimming, Surfing, Photography etc.).
2. WHEN a User submits the trip form with all required fields completed and passing validation, THE System SHALL create a Trip record and trigger AI Advice generation for all Categories (Accommodation, Transportation – Driving, Transportation – Public Transport, Transportation – Ride-Hailing Services, Money, WiFi & Mobile Data, Clothing & Accessories, Food & Tipping Culture, Laundry, Groceries & Drinking Water, Activities, Weather, Safety, Local Etiquette, Miscellaneous).
3. THE System SHALL require all fields (destination, travel date range, travel mode, budget range, travel style, activity preferences) to be completed before creating any Trip record.
4. IF a User submits the trip form with one or more required fields missing or invalid, THEN THE System SHALL display field-level validation errors on each failing field and SHALL NOT create a Trip record.
5. IF a User enters a travel start date earlier than the current calendar date, THEN THE System SHALL display a validation error on the start date field and SHALL NOT create a Trip record.
6. WHEN the travel end date precedes the travel start date, THE System SHALL display a validation error on the date range field and SHALL NOT create a Trip record.
7. THE System SHALL support exactly 10 hard-coded Destinations at launch: Costa Rica, Mallorca, and 8 additional destinations defined at deployment time.

### Requirement 4: AI Advice Generation and Persistence

**User Story:** As the System, I want to generate AI-powered travel advice once per unique cache key and persist it, so that repeated queries for the same context are served from storage rather than from the AI provider.

#### Acceptance Criteria

1. WHEN a Trip is created, THE LLM_Adapter SHALL generate AI Advice for each Category using the trip's destination, travel month, traveller type, and budget range as context.
2. WHEN a request for AI Advice is received, THE Advice_Store SHALL check whether an AI Advice record already exists for the Cache Key (destination, month, traveller_type, budget_range), treating all Cache Key components as case-insensitive.
3. WHEN matching AI Advice exists in the Advice_Store, THE System SHALL serve the cached advice and SHALL NOT make a new AI provider call.
4. WHEN no matching AI Advice exists, THE LLM_Adapter SHALL call the configured AI provider; WHEN the AI provider returns a successful response, THE LLM_Adapter SHALL store the response in the Advice_Store before returning it to the caller; IF the AI provider does not return a response within 30 seconds, THE LLM_Adapter SHALL time out the request and treat it as an error.
5. THE LLM_Adapter SHALL expose a single integration interface that can route requests to one or more AI model providers without requiring changes to calling code.
6. THE Advice_Store SHALL store AI Advice records indexed by the Cache Key (destination, month, traveller_type, budget_range).
7. WHEN the LLM_Adapter receives an error response or timeout from an AI provider, THE System SHALL log the error details server-side and display a user-facing message indicating that advice could not be loaded at this time.
8. IF the Advice_Store fails to write a new AI Advice record, THEN THE System SHALL log the write failure server-side, return the AI-generated advice to the caller for this request, and display a user-facing message indicating that the advice could not be saved and will not be cached.

### Requirement 5: Concise Category Cards (Home Page)

**User Story:** As a User, I want to see a summary card for each travel topic on the Home page, so that I can quickly scan the most important advice for my destination.

#### Acceptance Criteria

1. THE System SHALL display a Concise Card for each of the following 12 topics: Rental car, Parking, Public transport, Laundry, Airport transport, Mobile data, Cash needed, Tipping expected, Where to eat, Weather conditions, Safety rating, Mosquitos expected.
2. WHEN a User views the Home page, THE System SHALL display all 12 Concise Cards in a grid layout of at least 2 columns on viewports 600 px wide or wider, and in a single-column layout on viewports narrower than 600 px.
3. WHEN a User taps or clicks a Concise Card that is in the collapsed state, THE System SHALL expand the card to show the corresponding Expanded Card detail view; WHEN a User taps or clicks a Concise Card that is in the expanded state, THE System SHALL collapse the card back to the Concise Card view.
4. WHEN the AI Advice for a Category contains more than one sentence, where a sentence is defined as text ending with a period, exclamation mark, or question mark, THE System SHALL generate an AI summary of no more than one sentence for the Concise Card. WHEN the AI Advice contains exactly one sentence or fewer, THE System SHALL use the original text directly as the Concise Card summary.
5. WHILE the AI summary for a Concise Card is being generated, THE System SHALL display a loading placeholder in place of the summary text until generation completes.
6. IF the AI summary generation for a Concise Card fails, THEN THE System SHALL display the original AI Advice text as the Concise Card summary.
7. THE System SHALL display a link from the Home page to the Comprehensive View page for the active Trip.

### Requirement 6: Expanded Card Detail View

**User Story:** As a User, I want to open a detailed card view for any topic, so that I can read the full AI-generated answers to every sub-question in that Category.

#### Acceptance Criteria

1. WHEN a User opens an Expanded Card, THE System SHALL display the following structure: topic name, a "Recommended?" indicator with one of the values Yes / No / Unknown, the answer from the Concise view, and then each sub-question with its AI-generated answer displayed under the Category name as a labelled section header.
2. THE System SHALL populate Expanded Cards for all 15 Categories: Transportation – Driving, Transportation – Public Transport, Transportation – Ride-Hailing Services, Accommodation, Money, WiFi & Mobile Data, Clothing & Accessories, Food & Tipping Culture, Laundry, Groceries & Drinking Water, Activities, Weather, Safety, Local Etiquette, and Miscellaneous.
3. WHEN AI Advice for a sub-question is not applicable to the selected Destination, THE System SHALL display "Not applicable" rather than an empty field.
4. THE System SHALL display exactly the following sub-questions for each Category as defined in the product specification (no more, no less): Transportation – Driving (Is driving recommended? Are roads in good condition? Are car rentals recommended? Are there mountain roads that are difficult to drive? Is parking easy? Is parking widely available? What are the parking rules?); Transportation – Public Transport (Is public transport sufficient?); Transportation – Ride-Hailing Services (Should I book airport transport in advance? Are taxis/Uber readily available?); Accommodation (Which area should I stay in? Hotel, hostel or Airbnb? Private room or shared dorm? Is it social? Are accommodations likely to sell out?); Money (Should I bring cash in advance of the trip? Do most places accept card payment? Which cards are widely accepted? Is my budget appropriate for the destination? What is a realistic daily budget?); WiFi & Mobile Data (Should I buy an eSIM? Which eSIM provider is best? How reliable is mobile data? Is Wi-Fi generally reliable? Is the destination suitable for remote work?); Clothing & Accessories (What type of clothes should I pack? Should I pack long trousers/shirts? What type of clothes should I pack for my activity preferences? Do I need insect repellent? Do I need sunscreen? What SPF is recommended? Do I need a rain coat? Do I need an umbrella? Do I need a dry bag?); Food & Tipping Culture (Is tipping expected? Where do locals eat? What local dishes should I try? Is street food safe? What are average meal prices?); Laundry (Are there self-service laundrettes? How expensive are self-service laundrettes? Are there service wash laundrettes? How expensive are service wash laundrettes? Do laundrettes take cash and/ or card?); Groceries & Drinking Water (What supermarkets are recommended? Is tap water safe to drink? What are popular pharmacies? Are ATMs widely available? Is sunscreen expensive?); Activities (Which activities are worth booking in advance according to my activity preferences? Which activities are tourist traps? Should I book ahead? What are hidden gems? Is it advised to swim in nearby beaches?); Weather (Are rain showers common? Is it mostly sunny? Does it rain occasionally? Is drizzle rain common? Are there specific times to avoid going outside?); Safety (Is it safe for solo travellers? Are there scams to watch out for? Which areas should I avoid? Is phone theft common? Is it safe at night? Is it safe for women to walk around alone?); Local Etiquette (TBD – populated when defined); Miscellaneous (What are things I wish I had known?).
5. WHILE AI Advice for an Expanded Card has not yet been fetched or generated, THE System SHALL display a loading state for each unanswered sub-question until the advice is available.

### Requirement 7: User Voting on AI Advice

**User Story:** As a User, I want to vote on whether AI advice is accurate or outdated, so that the quality of advice improves over time based on real traveller feedback.

#### Acceptance Criteria

1. THE System SHALL display three voting actions on each AI Advice answer: 👍 Accurate, 👎 Outdated, and ➕ Add experience.
2. WHEN a User casts a 👍 Accurate or 👎 Outdated vote on an AI Advice answer that they have not previously voted on, THE Advice_Store SHALL create a vote record linked to that AI Advice record and the User's account.
3. WHEN a User selects ➕ Add experience, THE System SHALL present a text input, accepting up to 500 characters, allowing the User to submit a personal experience note independently of any 👍 Accurate or 👎 Outdated vote.
4. WHEN a User submits a personal experience note of 1 to 500 characters, THE Advice_Store SHALL save the note linked to the AI Advice record and the User's account, and THE System SHALL display a confirmation indicating the note was saved.
5. WHEN a User has already voted on a specific AI Advice answer, THE System SHALL display the User's existing vote selection and allow the User to change or retract it.
6. WHEN a User changes their existing vote on a specific AI Advice answer, THE Advice_Store SHALL update the existing vote record to the new vote value.
7. WHEN a User retracts their existing vote on a specific AI Advice answer, THE Advice_Store SHALL remove the vote record for that User and AI Advice answer.
8. IF a User submits an experience note exceeding 500 characters, THEN THE System SHALL display a character-limit validation error and SHALL NOT save the note.

### Requirement 8: Travel Destinations Page

**User Story:** As a User, I want to view all my upcoming and past trips in one place, so that I can manage my travel plans and navigate to advice for each trip.

#### Acceptance Criteria

1. WHEN a User views the Travel Destinations page and has at least one trip, THE System SHALL display two named sections: "Upcoming destinations" containing trips where the start date is on or after today or where today falls between the start and end dates (inclusive), and "Past destinations" containing trips where the end date is before today.
2. WHEN a User views the Travel Destinations page and has no trips, THE System SHALL display both the "Upcoming destinations" and "Past destinations" section headings with an empty-state message in each, prompting the User to add their first destination via a link that navigates to the Add Travel Destination form.
3. WHEN a User taps a trip in either section, THE System SHALL navigate to the Home page for that Trip, showing the 12 Concise Cards contextualised to that trip.
4. THE System SHALL display an "Add new destination" link on the Travel Destinations page that navigates to the Add Travel Destination form.

### Requirement 9: User Profile Page

**User Story:** As a User, I want to manage my profile settings and account preferences in one place, so that I can keep my information up to date and control my account.

#### Acceptance Criteria

1. THE System SHALL display the following on the User Profile page: current username (derived from first and last name), current profile image, an option to modify the username, an option to modify the profile image, a link to the Terms & Conditions, a Delete account button, and a Logout button.
2. WHEN a User saves a modified username, THE Profile_Service SHALL validate that the new username is non-empty and does not exceed 255 characters before persisting the change; IF the username fails validation, THEN THE Profile_Service SHALL display a field-level validation error and SHALL NOT save the change.
3. WHEN a User saves a modified profile image, THE Profile_Service SHALL enforce the same file format and size constraints defined in Requirement 2, Acceptance Criterion 7; IF the uploaded file does not meet these constraints, THEN THE Profile_Service SHALL display a field-level validation error and SHALL NOT save the file.
4. WHEN a User taps the Logout button, THE Auth_Service SHALL invalidate the User's session and redirect them to the login page.
5. WHEN a User taps the Delete account button, THE System SHALL display a confirmation dialog containing a warning message, a confirm deletion button, and a cancel button; IF the User taps the cancel button or dismisses the dialog, THE System SHALL close the dialog and return focus to the User Profile page without deleting any data.
6. IF a User confirms account deletion by explicitly tapping the confirm button in the dialog, THEN THE System SHALL permanently delete the User's profile, all associated Trip records, and all Vote records, and SHALL redirect the User to the login page; IF the deletion operation fails, THEN THE System SHALL display an error message, leave the account intact, and return the User to the User Profile page.

### Requirement 10: Responsive and Mobile-Friendly UI

**User Story:** As a User, I want the application to be fully usable on my mobile phone, so that I can look up travel advice on the go.

#### Acceptance Criteria

1. THE System SHALL render all pages correctly on viewport widths from 375 px (small mobile) upward, including wide desktop viewports of 1920 px and above, without horizontal scrolling or content overflow.
2. THE System SHALL meet WCAG 2.1 Level AA colour contrast requirements on all interactive and text elements across all pages.
3. WHEN a User navigates between pages, THE System SHALL complete the client-side route transition within 300 ms on a standard 4G connection (measured from the navigation trigger to the new page being interactive).
4. THE System SHALL use a mobile-first CSS approach, applying base styles for the narrowest supported viewport (375 px) and overriding those styles at defined breakpoints for wider viewports.
5. THE System SHALL ensure all interactive elements (buttons, links, form fields) have a minimum touch target size of 44 × 44 px on mobile viewports.
